# handoff-load — 過去の引き継ぎを読み込む

過去のセッションが `handoff` で書いた引き継ぎを読み、作業を再開できる状態にする。
**このスキルはファイルを書き換えない。**

## 自発的に呼ばない

人間が明示的に呼んだときだけ動く。

新規セッションで何を始めるかは、こちらからは分からない。無関係な作業に古い引き継ぎを
持ち込むと、存在しない前提を抱えたまま作業が進む。害のほうが大きい。

## 手順

### 1. 引き継ぎのあるディレクトリを決める

`${CLAUDE_PLUGIN_DATA}/<project-slug>/`。`<project-slug>` は次で得る。

```bash
printf 'cwd=%s\nslug=%s\n' "$(pwd)" "$(pwd | sed 's#[^a-zA-Z0-9_-]#-#g')"
```

置換規則は `pre-compact.sh` と `handoff` に一致させてある。組み立て直さない。

止まるべき条件が 2 つある。どちらも「引き継ぎが無い」と報告してはならない場面で、
無いと言い切ると人間は誤った前提のまま作業を始める。

- **`${CLAUDE_PLUGIN_DATA}` が絶対パスに展開されておらず `${CLAUDE_PLUGIN_DATA}` という
  文字列のまま見えている。** このシェル変数は Bash ツールの環境には存在しないので、
  シェル経由でも解決できない。推測して探すと、「引き継ぎが無い」のか「見に行った場所が
  違う」のか区別がつかなくなる
- **`cwd` が、セッション開始時にシステムから提示された作業ディレクトリと違う。**
  Bash ツールの作業ディレクトリはセッション中の `cd` で移動し、そのまま保持される。
  移動後に呼ぶと別 slug のディレクトリを見に行き、実際には引き継ぎがあるのに
  `NO_DIR` になる。上と同じ誤報を、別の経路で起こす

### 2. 候補を集める

```bash
d=<手順1で確定したディレクトリ>
[ -d "$d" ] || { echo "NO_DIR"; exit 0; }
[ -n "$(ls "$d"/*.md 2>/dev/null)" ] || { echo "NO_FILES"; exit 0; }
[ -f "$d/latest" ] && printf 'latest=%s\n' "$(cat "$d/latest")"
for f in "$d"/*.md; do
  printf '%s\t%s\t%s\t%s\n' \
    "$(basename "$f" .md)" \
    "$(sed -n 's/^updated: //p' "$f" | head -1)" \
    "$(sed -n 's/^continues_from: //p' "$f" | head -1)" \
    "$(sed -n '/^## いま何をしているか$/,/^## /{ /^## /d; /^$/d; p; }' "$f" | head -1)"
done
```

出力は `session_id`／`updated`／`continues_from`（無ければ空）／
`## いま何をしているか` の先頭 1 行、のタブ区切り。

`## いま何をしているか` は §5.1 で固定された見出し文字列で、`session-start.sh` と
`handoff` も同じ文字列に依存している。**言い換えると抽出が静かに失敗する**ので、
上のコマンド中のこの文字列を書き換えないこと。

### 3. 引き継ぎが無ければそこで終わる

`NO_DIR` または `NO_FILES` なら「このプロジェクトの引き継ぎは無い」と報告して終了する。

**他の場所を探し始めない。** 別プロジェクトのディレクトリ、`~/.claude/projects/` の
memory、git のログ、それらしい名前の markdown — どれも引き継ぎではない。
無いものを埋めようとすると、人間は「読み込めた」と受け取ったまま、
実際には無関係な材料の上で作業を始めることになる。

### 4. 候補一覧を出して人間に選ばせる

`continues_from` で連なるファイル群は 1 件に畳む。畳んだ件数を併記する。

連鎖は「同じ作業を新規セッションで仕切り直した」履歴なので、続きとして意味を持つのは
末端だけ。畳まないと、`## いま何をしているか` がほぼ同じ項目が並び、
どれが最新の続きか判別できなくなる。

**畳む先は連鎖の「葉」**、つまり他のどのファイルからも `continues_from` で
参照されていないものを指す。`updated` が最大のものではない。開いたままのセッションが
後継の作成後に自分のファイルを更新すると、この 2 つは食い違う。

**葉が複数あるときは畳まない。葉ごとに 1 件として出す。**
同じ引き継ぎを 2 つのセッションが読み込むと連鎖は枝分かれし（A←B と A←C）、
どちらも生きている作業になる。1 件に畳むと、片方が候補一覧から黙って消える。
§4.4 が session_id 単位でファイルを分けているのは、まさにこの並行セッションのため。

`latest` に記録された session_id を含む行を先頭に置き、印を付ける。
`latest` が畳まれた側（非葉）を指していても、それを含む連鎖の行に印を付ければよい。

```text
このプロジェクトの引き継ぎ:

  1) 2時間0分前  CSV ダウンローダの再試行処理を実装中   ← latest（3 件を集約）
     9f1c2ab4-3d5e-4c81-b0a2-77e19f3c4d61
  2) 3日前       型注釈の整備
     4b8e1c72-9a04-4f36-8d13-2e5a7c9b0f88

どれを読み込みますか。
```

session_id を併記するのは、要約 1 行が酷似する候補が並んだときに人間が区別できなくなる
のを避けるため。経過時間の表記はフックの `elapsed_ja`（`lib.sh`）に合わせる:
`%d秒前` / `%d分前` / `%d時間%d分前` / `%d日前`。
同じ引き継ぎの鮮度が、フックの注入とこの一覧とで違う書き方になると読み手が混乱する。

**候補が 1 件だけでも人間に確認する。** 並行して別のセッションが動いていると、
`latest` が意図と食い違いうる。確認を省くと、違うものを黙って読み込むことになる。

経過時間は `updated` から計算する。鮮度が見えないと、古い引き継ぎを最新と誤認する。

### 5. 選ばれたファイルを全文読む

`Read` で全文を読む。セクションの取捨選択はしない。

新規セッションはコンテキストが空なので削る動機が無い。ここで削ると、
`handoff` が全セクションを書いた意味が消える（記録は常に全セクション、
量を絞るのは compact 直後の注入だけ、というのが設計）。

### 6. 要約して報告する

人間には「背景・目的」「いま何をしているか」「未完了・次の一手」と、
`updated` からの経過時間を要約して伝える。

```text
引き継ぎを読み込みました（最終更新: 2時間前）

背景・目的: 定時バッチが対象 API の 429 で落ちる事象への対処
いま: CSV ダウンローダの再試行処理を実装中。仕様は決まったが実装は未着手
次の一手:
  - test_download_csv.py に 429 応答のテストを追加（テストファースト）
  - 実装は上記テストが赤になってから
```

これは表示の都合であって、コンテキストには全セクションが載っている。
「試して駄目だったこと」や「注意」も読んだうえで作業すること。

### 7. 読み込んだ session_id を覚えておく

このセッションで最初に `handoff` を呼ぶとき、frontmatter の `continues_from` へ
この session_id を書く。手順 4 の集約はこの値だけを頼りにしているので、
書かないと次の仕切り直しで連鎖が切れ、候補一覧に同じ作業が二重に並ぶ。
