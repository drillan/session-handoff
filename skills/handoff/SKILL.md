# handoff — 作業状態を書き出す

このセッションで積み上がった作業状態を、1 つの markdown ファイルへ書き出す。
compact でコンテキストが要約されても、また別のセッションで仕切り直しても、
そこから作業を再開できるようにするのが目的。

読み込みは `handoff-load` の担当。このスキルは**書くだけ**。

## なぜファイルなのか

compact の要約は「何をしたか」を残すが「何をしなかったか」を落とす。
どの選択肢を試して駄目だったかは、失うと最も高くつく情報で、
かつ要約が最も落としやすい。そこを明示的に保全するための器がこのファイル。

## 手順

### 1. パスを決める

保存先は `${CLAUDE_PLUGIN_DATA}/<project-slug>/<session_id>.md`。

必要な値は次の 1 コマンドで得る。

```bash
printf 'session_id=%s\ncwd=%s\nslug=%s\n' \
  "$CLAUDE_CODE_SESSION_ID" \
  "$(pwd)" \
  "$(pwd | sed 's#[^a-zA-Z0-9_-]#-#g')"
```

`sed` の置換規則は `pre-compact.sh` と同一で、同じディレクトリを指すために必要。
自分で slug を組み立て直さず、このコマンドの出力をそのまま使う。

パスを組み立てる前に、止まるべき条件が 3 つある。いずれも推測で埋めず、
そこで報告して終わる。

- **`session_id=` が空、または 16 進数字とハイフン以外を含む。**
  この値はパスの構成要素になる。`lib.sh` の `handoff_path` も同じ検査をして、
  不正なら黙って直さず失敗させている。ここだけ緩めると `.md` という名前の
  ファイルや、空の `latest` ができる
- **`cwd` が、セッション開始時にシステムから提示された作業ディレクトリと違う。**
  Bash ツールの作業ディレクトリはセッション中の `cd` で移動し、そのまま保持される。
  移動後に呼ぶと slug が変わり、フックが書く場所とは別ディレクトリになる
- **`${CLAUDE_PLUGIN_DATA}` が、この指示を読んでいる時点で絶対パスに展開されておらず、
  `${CLAUDE_PLUGIN_DATA}` という文字列のまま見えている。**
  このシェル変数は Bash ツールの環境には存在しないので、シェル経由でも解決できない。
  それらしいパスを推測して書き込むと、フックが読む場所とは別の場所にファイルが残り、
  引き継ぎが成立しないのに成功したように見える。これが最も避けたい失敗の形

3 つとも通ったら、**保存先パスをここで確定して固定する。以降このパスを変えない。**
手順 6 で `latest` を書くときも、このパスの親ディレクトリを使う。

なお `/handoff` は subagent の中では実行しない。`CLAUDE_CODE_SESSION_ID` がメイン
セッションと同じ値になるかは確認されておらず（仕様 §11.1）、違えば別 session_id の
ファイルができる。**subagent の中にいるかを判定する手段は無い**
（`CLAUDE_CODE_CHILD_SESSION` はメインループでも設定されていた）ので、
これは検査ではなく運用上の約束。`/handoff` を subagent へ dispatch しないこと。

### 2. 既存ファイルを読む

ファイルがあれば `Read` する。無ければ新規作成。

`## 自動追記ログ` 以降は `pre-compact.sh` の領域で、**このスキルは一切書き換えない**（読むのは可）。
`Write` は全文を書き戻すので、`Read` で得たログをそのまま末尾に含めること。
ここを落とすと、compact 時に記録された git の状態が消える。

### 3. 読んだファイルがフック製だった場合

`updated_by` が `pre-compact-hook` なら、それは `/handoff` を実行しないまま compact が
走ったときにフックが作ったスタブで、`## いま何をしているか` に次の警告文が入っている。

```
⚠ /handoff を実行しないまま compact が発火した。意味情報は記録されていない。
下記の `## 自動追記ログ` にある git の状態だけが手がかり。
```

この警告は**削除して、実際の内容で置き換える**。横に書き足さない。
警告はもう真ではなくなっているのに、残すと次に読む人が
「意味情報は無い」と信じて本文を読み飛ばす。

### 4. 全セクションを書く

見出しは以下の 9 つ。**文字列を変更しない**。
`session-start.sh` と `handoff-load` が見出しを文字列一致で探すので、
言い換えた瞬間に抽出が静かに失敗する。

```markdown
## 背景・目的
## いま何をしているか
## 完了したこと
## 未完了・次の一手
## 決定と根拠
## 試して駄目だったこと
## 恒久知見の候補
## 注意
## 自動追記ログ
```

このうち書くのは先頭 8 つ。`## 自動追記ログ` は読んだ内容をそのまま残す。

**新規作成のときも、`## 注意` の後に `---` 区切りと空の `## 自動追記ログ` 見出しを必ず置く。**
この見出しが無いと、次に `pre-compact.sh` がファイル末尾へ git の状態を追記したとき、
それが `## 注意` セクションの内側に入る。`session-start.sh` は `^## ` で切るので、
git のノイズが「注意」として compact 後のコンテキストに注入される。

場面によって書き分けない。compact 用と新規セッション用で内容を変えたくなるが、
分岐するのは読み込み側であって記録側ではない。常に 8 セクションすべてを埋める。

既存の記述は消さず、古くなった項目だけを書き換える。

各セクションに何を書くか:

- **背景・目的** — なぜこの作業をしているのか。新規セッションではこれが完全に欠落するので、
  ファイル内で自己完結させる。対象ファイルのパスもここに書く
- **いま何をしているか** — 現在地。1〜3 行
- **完了したこと** — 終わって検証済みのもの
- **未完了・次の一手** — チェックボックス形式。次に手を動かす人が最初に読む場所
- **決定と根拠** — 決めたことと「なぜ」。却下した案とその理由も書く
- **試して駄目だったこと** — 試行して駄目だった選択肢と、駄目だった理由
- **恒久知見の候補** — 会話を超えて価値のある知見の**列挙のみ**
- **注意** — 踏むと痛い落とし穴
- **自動追記ログ** — 触らない

### 5. frontmatter を更新する

```yaml
---
session_id: <手順1で得た session_id>
project: <手順1で得た cwd>
updated: <書き込み直前に採り直した時刻>
updated_by: handoff-skill
continues_from: <handoff-load で読み込んだ元の session_id>
---
```

`updated` は `Write` の直前に `date --iso-8601=seconds` で採り直す。
本文を書き終えてから採ること。先に採った時刻を使い回すと、執筆にかかった分だけ古い値になる。
`handoff-load` はこの値で鮮度を表示し、`session-start.sh` は経過時間を計算するので、
ずれると「最後に書いたはずの引き継ぎが、他より古く見える」ことが起きる。

`continues_from` は、このセッションが `handoff-load` から始まった場合のみ書く。
そうでなければ**項目ごと省く**。空文字や `null` を書かない。
`handoff-load` の候補一覧は、この項目をたどって連鎖を追い、生きているものごとに
1 件へ畳む。値が無いと連鎖が切れ、同じ作業が候補一覧に二重に並ぶ。

`updated_by` は、読み込んだファイルが `pre-compact-hook` だった場合も含め、
必ず `handoff-skill` に変える。この値が「意味情報が入っているのか機械ログだけなのか」の
唯一の目印になっている。

### 6. 書き込んで `latest` を更新する

`Write` で保存する。ディレクトリが無ければ先に作る（このプロジェクトで一度も
compact が走っていない場合、まだ存在しない）。

続けて `latest` に session_id だけを書く（末尾に改行を入れない）。
書き込み先は**手順 1 で固定した保存先パスの親ディレクトリ**で、組み立て直さない。

```bash
printf '%s' "$CLAUDE_CODE_SESSION_ID" > <手順1で固定した保存先パスの親ディレクトリ>/latest
```

`latest` は「このプロジェクトで最後に更新された引き継ぎ」を指す。
`handoff-load` はこれを候補一覧の先頭に置くので、更新を怠ると
古いセッションが最新の顔をして先頭に並ぶ。

### 7. 報告する

こう報告する。

```text
引き継ぎを更新しました: 背景・目的 / いま何をしているか / 未完了・次の一手 / 試して駄目だったこと

続け方:
  a) このセッションで続行 — compact が走れば自動で復元されます
  b) 新規セッションで仕切り直し — 新しいセッションで /handoff-load を呼んでください
```

セクション名は実際に更新したものを挙げる。

## 書くときの制約

- **会話から確認できないことを書かない。** 不明なものは「不明」と明記する。
  引き継ぎファイルは次に読む人が疑わずに信じる前提の文書なので、
  もっともらしい推測が 1 つ混ざるだけで全体の信頼性が落ちる
- **「試して駄目だったこと」を空にしない。** 該当が無ければ「なし」と書く。
  空欄は「調べていない」と「無かった」を区別できない
- **確証のない事実には「未検証」を付す。** 特に「恒久知見の候補」は
  そのまま長期記憶へ昇格しうるので、検証済みかどうかの区別が要る
- **保存の代行をしない。** chiso や auto-memory への保存はこのスキルの領域外。
  「恒久知見の候補」に列挙するところまでで止め、保存するかどうかは人間が決める
