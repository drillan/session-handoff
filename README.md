# session-handoff

compact をまたいで、および新規セッションへ、作業状態を引き継ぐ Claude Code プラグイン。

## 解こうとしている問題

compact の要約は「何をしたか」を残すが「何をしなかったか」を落とす。
どの選択肢を試して駄目だったかは、失うと最も高くつく情報で、かつ要約が最も落としやすい。

同じ袋小路に再突入する、既に却下した案をもう一度提案する、といった形で表面化する。
このプラグインは、その手の情報を明示的にファイルへ保全し、compact 直後に呼び戻す。

## 導入

```bash
git clone git@github.com:drillan/session-handoff.git ~/repo/session-handoff
ln -s ~/repo/session-handoff ~/.claude/skills/session-handoff
```

clone 先はどこでもよい。効いているのは 2 行目の `~/.claude/skills/` へのシンボリックリンクのほう。

次回セッションから `session-handoff@skills-dir` として自動で読み込まれる。
marketplace への登録も `settings.json` の編集も要らない。

`claude plugin list` に `✔ loaded` で出れば導入できている。

## 使い方

コマンドは 2 つ。書く側と読む側で分かれている。

| コマンド | 何をするか | いつ使うか |
| --- | --- | --- |
| `/handoff` | いまのセッションの作業状態を書き出す | 作業が一区切りしたとき、長い試行錯誤の直後、compact が近いとき |
| `/handoff-load` | 過去の引き継ぎを読み込む | 新規セッションや `/clear` の直後に、前の続きをやりたいとき |

`/handoff-load` は自発的には起動しない。新規セッションで何を始めるかは分からず、
無関係な作業に古い引き継ぎを持ち込むほうが害が大きいため。

## 動作

```
作業中 ──/handoff──▶ 引き継ぎファイル（意味情報を書く）
                          │
compact 発火               │
  ├─ PreCompact ───────────┤ git の状態を「自動追記ログ」へ追記
  │                        │
  └─ SessionStart(compact) ┴─▶ 3 セクションを抜き出して stdout へ
                                → compact 直後のコンテキストへ入る
```

自動 compact でも手動の `/compact` でも同じ経路を通る。フックで拾うので、
コンテキストが尽きかけていて `/handoff` を呼ぶ余裕が無い場面でも機械ログは残る。

注入するのは「試して駄目だったこと」「いま何をしているか」「未完了・次の一手」の
3 セクション（上限 2500 文字）。compact 直後はコンテキストが逼迫しているので、
残りはファイルパスの案内だけにして、必要なら Claude が `Read` で取りに行く。

**この並びは優先順位。** 2500 文字に収まらないときは後ろから丸ごと落とし、
落としたセクション名を明記する。要約が最も確実に落とすのが「試して駄目だったこと」
なので、逼迫時に最後まで残すのもそこにしている。

新規セッションで `/handoff-load` を使うときは全文を読む。コンテキストが空なので削る理由がない。

## 引き継ぎファイルの置き場所

```
~/.claude/plugins/data/session-handoff-skills-dir/<project-slug>/
├── <session_id>.md   引き継ぎ本体
└── latest            最後に更新されたセッションの session_id
```

`<project-slug>` は作業ディレクトリの絶対パスの `[^a-zA-Z0-9_-]` を `-` に置換したもの。
プロジェクトのリポジトリ内には何も書かない。

session_id 単位に分けてあるのは、worktree などで並行するセッションが 1 ファイルを
奪い合わないため。

## テスト

```bash
bash tests/run.sh
```

bats も shellcheck も要らない。必要なのは bash・git・jq と、GNU coreutils の `date`。

`date -d` と `date --iso-8601=seconds` を使っているので、**macOS の BSD date では
経過時間の算出が動かない**。Linux 前提の実装で、他プラットフォームは検証していない。

## 既知の制約

- **`--resume` / `--fork-session` では自動注入しない。** どちらも会話履歴を復元するので、
  そこへ引き継ぎを注入しても大半が重複する。仕切り直しは `/handoff-load` を明示的に呼ぶ
- **引き継ぎファイルは自動削除しない。** 溜まったら手で消す
- **`/handoff` を呼ばないまま compact が走ると、機械ログだけが残る。** その場合の
  引き継ぎファイルには「意味情報は記録されていない」という警告が入り、
  compact 直後にもその警告が注入される。何も無いのに何かあるように見えることはない
- **description による起動判定は未測定。** 測定に使うハーネスが本物のスキルを検出できず、
  全件 0 を返すため（設計文書 §11）。誤起動しない証拠も、誤起動する証拠も無い
